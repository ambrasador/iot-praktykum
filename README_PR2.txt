4. ФАЙЛИ КОМПЛЕКТУ, ЯКІ З’ЯВЛЯЮТЬСЯ В ПР2 (kit/)
====================================================================================================
Інструменти (kit/tools) — 2 файли. Запуск: node kit/tools/<ім’я>.mjs з кореня практикуму.
  serve.mjs, api.mjs
      Стенд API з історією варіанта (окремий термінал); HTTP-клієнт без curl і jq.

Контроль (kit/lib/checks)
  pr02.mjs
      Контроль ПР2: 20 пунктів (рівень «3» — 8, «4» — 6, «5» — 6). Звіряє журнал, файли й запуски
      коду застосунку з очікуваними числами паспорта.

Бібліотеки й стенди (kit/lib) — 4 файли
  bed-proc.mjs
      Запуск стенду окремим процесом: збій у коді студента не валить перевірку, а стає підказкою
  bed.mjs
      Стенд API для ПР2–ПР4: застосунок студента, база з історією варіанта (засіяна через справжнє
      приймання) і «пристрої», що підтверджують команди; усе в одному процесі.
  cases.mjs
      Набори допустимих і недопустимих значень за описом параметрів у паспорті (команди,
      налаштування)
  http.mjs
      Мінімальний HTTP-клієнт для перевірок: повертає { status, headers, body }

5. ЯК ЗАПУСТИТИ
====================================================================================================
Журнал track.json і каталоги pr01…pr08 уже створено в ПР1. Вхідний контроль ПР2 починається з
перевірки журналу ПР1: помилка в попередній роботі показується тут.

Вільним має бути порт 3100: на ньому працює стенд API (node kit/tools/serve.mjs у окремому
терміналі).

Команди інструментів, як їх наведено в тексті роботи (підрозділ 2.4; повні параметри — там):
  node kit/tools/serve.mjs
  node kit/tools/api.mjs GET /__bed/info --max 6
  node kit/tools/api.mjs GET /devices --max 2
  node kit/tools/api.mjs GET "/telemetry?device=bed-01&metric=soil_moisture&from=2025-11-02T00:00:00Z&to=2026-10-15T00:00:00Z&agg=count&interval=1mo"
  node kit/tools/api.mjs GET "/alerts?device=bed-01&metric=soil_moisture&from=2026-10-08T00:00:00Z&to=2026-10-15T12:00:00Z&op=lt&threshold=28&hysteresis=2&min_duration=900"

Контроль:
  node kit/tools/verify.mjs pr02                    рівень, заявлений при init
  node kit/tools/verify.mjs pr02 --level 4          показати, скільки лишилося до рівня «4» (або 5)
  node kit/tools/verify.mjs pr02 --declared-only    пропустити довідкові блоки рівнів вище заявленого
Числа в журнал вносять командою node kit/tools/track.mjs set <ключ> <значення>; node kit/tools/track.mjs show друкує журнал.

6. ЩО ПЕРЕВІРЯЄ verify.mjs pr02
====================================================================================================
Пункти, які контроль друкує на демонстраційному варіанті 0 при рівні «5»; ✓ — пункт виконано. У
вашому варіанті формулювання збігаються, а очікувані числа свої.

Рівень «3» — 8 пунктів
  ✓ Вхідний контроль: ПР1 виконано (є рішення про режим приймання й ADR-001)
  ✓ Стенд піднято, історію варіанта прийнято повністю (метрики й діапазони з ПР1)
  ✓ Каталог метрик: periodSec кожної метрики пристроїв дорівнює T із паспорта
  ✓ Сирі дані вікна з паспорта: кількість рядків і сторінок при limit = 200
  ✓ Сповіщення за параметрами паспорта (< 28, гістерезис 2, 900 с): кількість епізодів
  ✓ Найдовший епізод: початок, тривалість у хвилинах, екстремум
  ✓ Команда set_fan: допустимі виклики дають 202, недопустимі — 400
  ✓ Файл pr02/requests.http: GET /telemetry, GET /alerts і POST …/commands із вашими параметрами

Рівень «4» — 6 пунктів
  ✓ Підібрані hysteresis і min_duration дають ті самі 5 епізодів: без розколу й без дрібних викидів
  ✓ Добові агрегати у двох зонах: до якої доби потрапила подія (UTC і Europe/Kyiv)
  ✓ Межі вікна: W_agg і W_alerts у добах, розрахункова кількість рядків із відповіді 400, кількість
    запитів на 730 діб
  ✓ Інтервал агрегації для графіка (діб і точок з паспорта): найменший допустимий і кількість точок
    у відповіді
  ✓ Налаштування пристрою: доменні ключі приймаються, значення поза межами — 400; без If-Match —
    428; застарілий — 412
  ✓ Коди сценарію умовного запису записано (pr02.settings_codes: 428, 412, 200)

Рівень «5» — 6 пунктів
  ✓ Пара (hysteresis, min_duration) стійка: зміна кожного значення на ±20 % не змінює набір епізодів
  ✓ max_gap, за якого розколений розривом інцидент зливається в один епізод
  ✓ Ідемпотентність: той самий ключ і тіло повертають ту саму команду; інше тіло з тим самим ключем
    — 422
  ✓ openapi.yaml: CommandRequest описує доменні команди з межами параметрів; contract.test.js
    проходить
  ✓ Розмір відповіді: байтів на рядок сирої сторінки (limit = 1000) і скільки рядків вміщує
    відповідь у 100 КіБ
  ✓ ADR-002 (контракт читання): межі вікна, інтервал, пара (hysteresis, min_duration), тригер
    перегляду

Оцінка дорівнює найвищому рівню, всі пункти якого виконано (і всіх нижчих). Опис рівнів і складу
звіту — у підрозділах 2.5 і 2.6 практикуму; повні тексти завдань — у додатку Б.
