3. ЩО ЦЯ РОБОТА СТВОРЮЄ Й ЗМІНЮЄ
====================================================================================================
З тексту практикуму, підрозділ 7.1:

  Результат — каталог pr07/ (calc.mjs, а для рівня «5» ще й adr-007.md), чотири нові файли тестів у
  greenhouse-monitor/jest/ — unit/domain-<код>.spec.js та integration/range-<код>.spec.js (рівень
  «3»), unit/rules-<код>.spec.js та integration/domain-<код>.spec.js (рівень «4») — і секція pr07 у
  журналі track.json. Код застосунку ця робота не змінює: мутанти вносять помилки лише в тимчасову
  копію. ПР8 починається з вхідного контролю за журналом цієї роботи (pr07.pyramid).

Файли, яких немає в еталонному застосунку, ви створюєте самі: calc.mjs, adr-007.md,
unit/domain-<код>.spec.js, integration/range-<код>.spec.js, unit/rules-<код>.spec.js,
integration/domain-<код>.spec.js.

Підручник: робота спирається на п. 7.1.1, 7.2.1, 7.2.2, 7.3.1–7.3.4, 7.4.1 і 7.4.3 підручника. Код
розділу 7 — у підручнику й у репозиторії greenhouse-monitor.

5. ЯК ЗАПУСТИТИ
====================================================================================================
Журнал track.json і каталоги pr01…pr08 уже створено в ПР1. Вхідний контроль ПР7 починається з
перевірки журналу ПР6: помилка в попередній роботі показується тут.

Команди інструментів, як їх наведено в тексті роботи (підрозділ 7.4; повні параметри — там):
  node kit/tools/qa-inputs.mjs
  node kit/tools/qa-mutants.mjs cmdset
  node kit/tools/qa-mutants.mjs cmdset --list
  node kit/tools/qa-mutants.mjs range
  node kit/tools/qa-mutants.mjs data
  node kit/tools/flaky.mjs
  node kit/tools/flaky.mjs --runs 300

Контроль:
  node kit/tools/verify.mjs pr07                    рівень, заявлений при init
  node kit/tools/verify.mjs pr07 --level 4          показати, скільки лишилося до рівня «4» (або 5)
  node kit/tools/verify.mjs pr07 --declared-only    пропустити довідкові блоки рівнів вище заявленого
Числа в журнал вносять командою node kit/tools/track.mjs set <ключ> <значення>; node kit/tools/track.mjs show друкує журнал.

6. ЩО ПЕРЕВІРЯЄ verify.mjs pr07
====================================================================================================
Пункти, які контроль друкує на демонстраційному варіанті 0 при рівні «5»; ✓ — пункт виконано. У
вашому варіанті формулювання збігаються, а очікувані числа свої.

Рівень «3» — 6 пунктів
  ✓ Вхідний контроль: код домену з ПР1–ПР6 на місці (діапазони метрик, RULES_<код> у push.js,
    профіль безпеки)
  ✓ План межових рядків за правилом підрахунку: діапазони, команди, налаштування, правила рівнів,
    епізоди
  ✓ Бюджет піраміди: час нижніх рівнів, залишок, кількість наскрізних сценаріїв і їхній перелік за
    пріоритетом
  ✓ Нестабільний тест: прогони для виявлення (95 і 99 %) і для підтвердження виправлення,
    лабораторний прогін зі своїм зерном
  ✓ Межові тести команд і налаштувань: jest/unit/domain-d0.spec.js зелений і вбиває всі мутанти меж
  ✓ Межові тести діапазонів метрик: jest/integration/range-d0.spec.js зелений і вбиває всі мутанти
    меж

Рівень «4» — 3 пункти
  ✓ Правила рівнів: jest/unit/rules-d0.spec.js бере пороги з RULES_<код> і вбиває всі мутанти
    порогів, гістерезису й напряму
  ✓ Епізоди й рівні: дев’ять мутантів підрозділу 7.2.2 (nextLevel, findViolations) убито
  ✓ Інтеграційний тест: jest/integration/domain-d0.spec.js (брокер Aedes, корінь «greenhouse»)
    зелений і вбиває три мутанти шляху

Рівень «5» — 3 пункти
  ✓ Карантин нестабільних тестів: мінімальний набір, після якого частка червоних прогонів не
    перевищує допуск
  ✓ Матриця «мутант × набір тестів»: 12 мутантів проти Jest unit, Jest integration і node:test;
    жоден не лишається непоміченим
  ✓ ADR-007: розділи й числа (e2e_max, n_fix, кількість тестів у карантині)

Оцінка дорівнює найвищому рівню, всі пункти якого виконано (і всіх нижчих). Опис рівнів і складу
звіту — у підрозділах 7.5 і 7.6 практикуму; повні тексти завдань — у додатку Б.
