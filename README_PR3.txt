3. ЩО ЦЯ РОБОТА СТВОРЮЄ Й ЗМІНЮЄ
====================================================================================================
З тексту практикуму, підрозділ 3.1:

  Результат — каталог pr03/ (calc.mjs, rt.env, adr-003.md), змінені main.js і mqtt-commands.js та
  секція pr03 у журналі track.json. Числа цієї роботи читають наступні: ПР4 бере транспорт, вікно
  шини та політику перепідключення для дашборда, ПР6 — ліміти з’єднань, ПР8 передає rt.env у
  Compose.

Файли застосунку, з якими працює робота, і розділ підручника, де кожен з’явився. Ви змінюєте
остаточні версії з каталогу greenhouse-monitor; лістинги розділу показують, як файл виглядав у підручнику.
  main.js                розділ 1  (у розділі 1 — перша версія файла, остаточна — у greenhouse-monitor)
  mqtt-commands.js       розділ 2

Файли, яких немає в еталонному застосунку, ви створюєте самі: calc.mjs, rt.env, adr-003.md.

Підручник: робота спирається на п. 3.1 (ціна питання), 3.3 (шина з вікном і Socket.IO), 3.4 (SSE),
3.6.2–3.6.3 (узгодження й перепідключення), 3.7 (вимірювання) та 3.8 (ємність і кілька екземплярів)
підручника. Код розділу 3 — у підручнику й у репозиторії greenhouse-monitor.

====================================================================================================
5. ЯК ЗАПУСТИТИ
====================================================================================================
Журнал track.json і каталоги pr01…pr08 уже створено в ПР1. Вхідний контроль ПР3 починається з
перевірки журналу ПР2: помилка в попередній роботі показується тут.

rt-smoke.mjs запускає ваш main.js із налаштуваннями pr03/rt.env і посередині прогону перезапускає
застосунок; налаштування pr03/rt.env ви створюєте в цій роботі.

Команди інструментів, як їх наведено в тексті роботи (підрозділ 3.4; повні параметри — там):
  node kit/tools/rt-smoke.mjs
  node kit/tools/storm-sim.mjs --u 600 --b 1 --c 30

Контроль:
  node kit/tools/verify.mjs pr03                    рівень, заявлений при init
  node kit/tools/verify.mjs pr03 --level 4          показати, скільки лишилося до рівня «4» (або 5)
  node kit/tools/verify.mjs pr03 --declared-only    пропустити довідкові блоки рівнів вище заявленого
Числа в журнал вносять командою node kit/tools/track.mjs set <ключ> <значення>; node kit/tools/track.mjs show друкує журнал.

6. ЩО ПЕРЕВІРЯЄ verify.mjs pr03
====================================================================================================
Пункти, які контроль друкує на демонстраційному варіанті 0 при рівні «5»; ✓ — пункт виконано. У
вашому варіанті формулювання збігаються, а очікувані числа свої.

Рівень «3» — 7 пунктів
  ✓ Вхідний контроль: ПР2 виконано (є історія, епізоди й requests.http)
  ✓ Трафік клієнта за добу, МБ: опитування, SSE, Socket.IO (формули п. 3.7.1 і константи довідки)
  ✓ Транспорт обрано з урахуванням обмежень паспорта (WebSocket, зворотний напрям) і ціни трафіку
  ✓ Ємність одного процесу за політикою за замовчуванням: U_cpu, U_mem, U_storm, U_max, що обмежує
  ✓ Застосунок запускається з доменом: main.js слухає корінь топіків, приймання без відхилень,
    rt.env містить TOPIC_ROOT
  ✓ Доставка без пропусків і зайвих точок у Socket.IO й SSE після перезапуску застосунку посеред
    потоку
  ✓ Команда проходить через брокер домену: POST → <корінь>/<пристрій>/commands → підтвердження →
    стан acked

Рівень «4» — 4 пункти
  ✓ Вікно шини: window_ms покриває розкид повідомлень звіту, у rt.env, один кадр на звіт, затримка в
    межах вимоги
  ✓ Політика перепідключення задовольняє правило п. 3.7.6 (b ≥ 1,5·U/C і c ≥ 2·U/C; для SSE retry ≥
    U/C)
  ✓ Імітація шторму (kit/tools/storm-sim.mjs): найгірший пік ≤ C, медіана повернення в межах вимоги,
    числа збігаються з журналом
  ✓ Ємність після налаштування: що обмежує тепер, розбиття кімнати / пам'ять, U_max ≥ U; обсяг
    узгодження після перезапуску

Рівень «5» — 4 пункти
  ✓ Гаряча кімната: k_max за бюджетом затримки розсилання (k·g ≤ бюджет) і на скільки кімнат розбити
  ✓ Розгортання без шторму: мінімальна кількість екземплярів і час розвантаження одного (U / N / ((N
    − 1)·C / 2))
  ✓ Захист від повільного клієнта: ліміт черги в допустимих межах, у rt.env, main.js його читає
  ✓ ADR-003 (канал реального часу): транспорт, вікно, політика перепідключення, екземпляри, ліміт
    черги, тригер перегляду

Оцінка дорівнює найвищому рівню, всі пункти якого виконано (і всіх нижчих). Опис рівнів і складу
звіту — у підрозділах 3.5 і 3.6 практикуму; повні тексти завдань — у додатку Б.
