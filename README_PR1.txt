4. ФАЙЛИ КОМПЛЕКТУ, ЯКІ З’ЯВЛЯЮТЬСЯ В ПР1 (kit/)
====================================================================================================
Інструменти (kit/tools) — 7 файлів. Запуск: node kit/tools/<ім’я>.mjs з кореня практикуму.
  init.mjs
      Створює журнал track.json і каталоги pr01 … pr08.
  track.mjs
      show, get <шлях>, set <шлях> <значення>: читання й запис журналу.
  verify.mjs
      Вхідний і вихідний контроль: verify.mjs prN [--level L] [--declared-only].
  gen-stream.mjs, ingest-run.mjs
      Потік «брудних» повідомлень вашого варіанта й прогін через ядро приймання.
  bench-ingest.mjs, burst-sim.mjs
      Вимір пропускної здатності шляху до бази; імітація черги під час сплеску.

Контроль (kit/lib/checks)
  pr01.mjs
      Контроль ПР1: 21 пункт (рівень «3» — 8, «4» — 8, «5» — 5). Звіряє журнал, файли й запуски коду
      застосунку з очікуваними числами паспорта.

Бібліотеки й стенди (kit/lib) — 11 файлів
  app.mjs
      Доступ до еталонного застосунку (каталог greenhouse-monitor поруч із kit/)
  episodes.mjs
      Еталонний пошук епізодів порушення порога, незалежний від alerts.js застосунку (правила — з п.
      2.5 підручника).
  expect.mjs
      Очікувані значення практикуму: з них складається ключ викладача, і з ними звіряє verify.mjs.
  formulas.mjs
      Формули підручника, потрібні практикуму (нумерація — за розділами підручника); усі функції
      чисті.
  oracle.mjs
      Еталонний класифікатор приймання, незалежний від коду застосунку: порядок перевірок і межі як
      у core.js (п. 1.4 підручника).
  passport.mjs
      Паспорти об'єктів: дані варіантів 1–5 і демонстраційного прикладу 0
  paths.mjs
      Корінь практикуму (каталог, у якому лежать kit/, greenhouse-monitor/, track.json і pr01…pr08)
  rng.mjs
      Відтворюваний генератор випадкових чисел: те саме зерно дає ту саму послідовність
  series.mjs
      Відтворювана історія стенду: чотири пристрої, сім (V3 — сорок) діб вимірювань із підкладеними
      подіями; зерно студента й варіант визначають фази, шум і розташування подій.
  track.mjs
      Журнал наскрізного проєкту track.json: числа й рішення кожної практичної роботи
  verify-core.mjs
      Каркас перевірки: кожен пункт — це {level, text, run}; run повертає true або рядок з підказкою

Дані й шаблони
  kit/domains/
    d0.json   Теплиця (демонстраційний приклад з підручника)
    v1.json   Агромоніторинг теплиці/поля
    v2.json   Розумний будинок
    v3.json   Облік комунальних послуг
    v4.json   Моніторинг транспортного парку
    v5.json   Інфраструктура громади
  kit/templates/adr.md
      Шаблон запису архітектурного рішення (ADR): розділи «Контекст», «Рішення», «Альтернативи»,
      «Наслідки». Використовують ПР1–ПР5: pr0N/adr-00N.md.
  kit/templates/pr01-ingest.extra.test.js
      Заготовка власних тестів меж предметних правил домену (ПР1, рівень «5»): копіюється в

Каталог domains/ потрібен усім роботам: паспорт варіанта читає lib/passport.mjs.

====================================================================================================
5. ЯК ЗАПУСТИТИ
====================================================================================================
Підготовка (один раз):
  1. Розпакуйте в порожній каталог (корінь практикуму) kod_rozdilu7.zip і архіви ПР1…ПР8 (або лише ті, до яких дійшли).
  2. (cd greenhouse-monitor && npm ci)
  3. node kit/tools/init.mjs --variant K --seed N --level L --name "Прізвище І. П."
      K — номер варіанта 1…5 (0 — демонстраційний приклад з підручника), N — ваш номер у журналі
      групи (зерно), L — рівень «3», «4» або «5». Команда створює журнал track.json і каталоги
      pr01…pr08.

Команди інструментів, як їх наведено в тексті роботи (підрозділ 1.4; повні параметри — там):
  node kit/tools/gen-stream.mjs
  node kit/tools/ingest-run.mjs
  node kit/tools/bench-ingest.mjs --journal WAL --sync FULL --size 1 --rows 3000 >> pr01/bench.txt
  node kit/tools/burst-sim.mjs --N 200 --m 4 --T 60 --seed 1 --mu 2600 --queue 1000 --out pr01/sim.json

Контроль:
  node kit/tools/verify.mjs pr01                    рівень, заявлений при init
  node kit/tools/verify.mjs pr01 --level 4          показати, скільки лишилося до рівня «4» (або 5)
  node kit/tools/verify.mjs pr01 --declared-only    пропустити довідкові блоки рівнів вище заявленого
Числа в журнал вносять командою node kit/tools/track.mjs set <ключ> <значення>; node kit/tools/track.mjs show друкує журнал.

6. ЩО ПЕРЕВІРЯЄ verify.mjs pr01
====================================================================================================
Пункти, які контроль друкує на демонстраційному варіанті 0 при рівні «5»; ✓ — пункт виконано. У
вашому варіанті формулювання збігаються, а очікувані числа свої.

Рівень «3» — 8 пунктів
  ✓ λ_avg записано й збігається з розрахунком за паспортом
  ✓ λ_peak записано й збігається з розрахунком
  ✓ Річний обсяг: мільйонів рядків і гігабайт
  ✓ Обрано допустимий режим приймання (A, B, C або D)
  ✓ Запас обраного режиму: частка допустимого піка, %
  ✓ Потік брудних повідомлень приймається так, як визначає паспорт (звірка з еталонним підсумком)
  ✓ ADR-001 має розділи «Контекст», «Рішення», «Альтернативи», «Наслідки»
  ✓ Скрипт розрахунку pr01/calc.mjs додано

Рівень «4» — 8 пунктів
  ✓ Виміряно λ для s = 1 і s = 500 (WAL + FULL); пакет швидший
  ✓ Параметри моделі c і u знайдено з двох вимірювань
  ✓ Передбачення λ(s) збігається з виміром для вашої кількості рядків у транзакції
  ✓ Час до переповнення черги брокера для режиму A
  ✓ Мінімальне вікно розсіювання звітів τ′
  ✓ Найбільше N, за якого обраний режим тримає запас
  ✓ Опитування чи push для дашборда: R_poll, частка порога, рішення
  ✓ Докази вимірювань: pr01/bench.txt

Рівень «5» — 5 пунктів
  ✓ Імітація сплеску виконана з параметрами паспорта (pr01/sim.json)
  ✓ Результат імітації узгоджений із формулою піка
  ✓ Втрати черги з sim.json перенесено в журнал (pr01.sim_dropped, pr01.sim_mu)
  ✓ Власні тести меж: щонайменше три, усі проходять
  ✓ ADR-001 містить тригер перегляду з числом N_max

Оцінка дорівнює найвищому рівню, всі пункти якого виконано (і всіх нижчих). Опис рівнів і складу
звіту — у підрозділах 1.5 і 1.6 практикуму; повні тексти завдань — у додатку Б.
